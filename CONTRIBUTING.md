# Contributing

Use a focused branch and pull request. Explain the user-visible change and include the actual verification commands/results. Follow DEVELOPMENT.md and TESTING.md.

Run Composer validation, Pint, PHP syntax checks, tests, audit and release sanitization. Include regressions when modifying money, authentication, privacy, destination fetching or installation behavior. Never include real operator credentials or data. Preserve MIT/dependency licensing. Update documentation and changelog when behavior changes.

Do not add centralized services, tracking or automatic payment defaults as incidental changes.
